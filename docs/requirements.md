# 产品需求

## 背景与目标

多个应用接入模型服务后，模型 ID、接入协议和备用策略容易分散在各应用的环境变量和代码里。上游模型下架或出现故障时，维护人员需要逐一确认哪些功能受影响，并分别调整配置。

Minato 让业务方登记功能点并持有固定调用别名。管理员在一处查看模型目录、调整模型和回退策略，按项目、环境、功能点统计 token。业务可以部署在本地或云端，通过 HTTP 和现有 OpenAI SDK 接入。

## 项目与接入流程

1. 管理员在 Minato 创建项目和环境，为环境签发 Key。项目按业务划分，例如 `demo-app`。多处部署可以共用一个环境的路由，测试环境可以单独配置和轮换 Key。
2. 业务用项目环境 Key 登记功能点，例如 `text-classification`，声明预设模型、调用协议和能力要求。相同功能点可以重复登记。管理员调整的模型与业务预设分别保存，业务重新启动后继续使用管理员设置。
3. Minato 返回固定别名，例如 `demo-app.production.text-classification`。业务通过网关 `/v1/responses` 或 `/v1/chat/completions` 发请求，`model` 传固定别名。路由生效后，日常换模型无需业务改配置或重新部署。
4. 管理员可以为每个功能点设置首选模型和有序备用列表。功能点没有匹配的备用时，从满足它能力要求的默认池继续选择。界面应能看出业务预设、管理员覆盖、当前生效配置及最近一次切换原因。

## 首版范围

| 需求 | 首版交付 |
| --- | --- |
| 项目管理 | 创建项目和环境，发放及撤销环境 Key，查看已注册功能点 |
| 接入 | HTTP 注册 API 和 OpenAI 兼容推理入口，提供可复现的端到端接入示例 |
| 模型来源 | 首批适配 CLIProxyAPI（CPA）和 OpenCode，定时及手动同步目录，显示来源、原始 ID、最近同步结果和可用状态 |
| 模型路由 | 为功能点调整首选和备用模型，支持能力约束、自动回退、预览和回滚 |
| 用量 | 按项目、环境、功能点、实际来源及模型查看请求、失败、回退和 token，区分上游报告值与缺失值 |
| 调用审计 | 按项目环境开启。开启后逐次记录调用，支持查看请求、响应或错误、回退过程和每次尝试的 token，并从详情复制 Prompt 或请求 JSON |
| 回放测试 | 从测试页新建请求，或从有可用请求内容的记录发起单次回放。可按当前路由运行，也可指定兼容的测试模型，支持调整 Prompt 和参数并对照原始结果 |
| 部署 | 本地验证环境及可移植的容器部署设计，适用于本地和云端环境 |

后续可扩展通用兼容网关、专用 SDK、预算告警及 embedding。对依赖持久化向量索引的应用，embedding 模型切换需与索引迁移一起验证。

## 调用审计与回放

- 内容审计默认关闭，由项目管理员按环境开启并设定保留期。基础用量仍可查看。开启后，调用列表可按时间、功能点、模型、请求 ID 和结果筛选。
- 调用详情展示客户端发送的 Prompt、消息角色、模型参数和最终收到的响应，包含失败或中断状态。实际来源、模型、耗时、回退原因和上游报告的 token 按尝试展示。详情支持复制单条消息、完整 Prompt 或请求 JSON，导出的内容排除认证凭证。
- 从调用详情进入回放编辑页，载入可用的原始输入和参数，可修改后选择当前路由或指定测试模型。回放会实际发起新推理并可能产生用量。结果与原记录并排展示，便于比较输出、实际模型、耗时和 token。回放单独标记并关联原调用，方便在用量视图中筛选。

## 首版验收

| 场景 | 预期结果 |
| --- | --- |
| 环境 Key 登记功能点 | 同一身份重复提交得到同一别名。其他项目或环境的 Key 无法登记或调用该别名 |
| 后台调整首选模型 | 只改变目标功能点的后续调用。服务重启并登记后仍沿用该配置。回滚可恢复上一版路由 |
| 模型目录变化 | 新模型出现在目录。暂时同步失败保留上次成功结果。确认下架后从自动路由候选剔除 |
| 首选来源不可用 | 同一 Responses 请求按预设顺序切到满足功能要求的备用模型，客户端能解析结果 |
| 请求格式错误或流式中断 | 格式错误直接返回。已经输出的流发生中断时，记录失败并结束该流 |
| 查看 token 用量 | 同一业务请求只计一次请求量。实际上游尝试可追踪，已报告的 token 可归因，缺失值显示为未知 |
| 开启或关闭内容审计 | 开启期间的成功、失败和流式中断均有可追踪记录，能看到实际采集到的请求和响应。关闭期间保留基础用量，详情无请求和响应正文 |
| 复制 Prompt 和发起回放 | 能复制完整消息或请求 JSON，在编辑页修改输入并发起测试。回放结果可与原调用比较，凭证未包含在复制内容里 |
| 原调用依赖历史会话或附件 | 编辑页显示缺失内容并允许补齐。资料完整时可提交测试 |
| 管理服务暂停或发布失败 | 推理沿用上一份经验证的路由，管理页反映发布状态 |

实现细节与验证顺序见[技术设计](design.md)。
