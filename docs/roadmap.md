# Minato MVP 实施计划

开发任务已按里程碑拆成独立文档。 [MVP Ticket 索引](tickets/README.md)

下一步先打通一条可重复的本地业务链路。用 API 创建项目和环境，签发 Key，注册功能点，发布两个模拟模型，再用标准 OpenAI 客户端通过固定别名完成推理和回退。把这条链路跑通后，再接真实目录、审计持久化、管理界面和单次回放。

LiteLLM `v1.85.0` 已用模拟上游验证 Responses、Chat 转换、流式终态用量、动态模型组和调用回调。默认回退会吞掉普通上游 `400`，因此 Minato 按错误类型选择备用，LiteLLM 负责每次上游调用和协议转换。Minato 的接口、数据库和运行时还待实现。 [本地兼容性验证](../tools/litellm-compat/README.md)

## 里程碑

| 阶段 | 依赖 | 交付与验收 |
| --- | --- | --- |
| M1 本地推理链路 | 已完成的 LiteLLM 本地验证 | 用 API 创建项目、环境和 Key，登记功能点并发布静态候选。OpenAI SDK 用固定别名完成 Responses 和 Chat 调用。首选 `429` 回退，普通 `400` 直接返回，环境隔离和 Key 撤销通过验证 |
| M2 目录同步与动态路由 | M1 | CPA、OpenCode 目录适配器、能力匹配、默认池和目录变化自动重算。验证拉取失败保留成功快照、确认下架后切换、模型恢复后按批准策略重新纳入，以及旧版请求继续走旧配置 |
| M3 用量与调用审计 | M1 的请求和尝试 ID | 采集与关联客户端请求、响应和 LiteLLM 尝试事件，支持用量查询、审计开关、正文保留期和权限。验证乱序去重、未知用量、流式断开、正文到期和采集写入失败 |
| M4 管理界面与单次测试 | M2 和 M3 的查询及写入接口 | 提供项目环境、模型来源、路由发布、用量、调用详情和测试页。能复制 Prompt 或请求 JSON，按当前路由或指定模型回放，比较输出、耗时和 token |
| M5 可自托管发布 | M1–M4 | 提供安装、升级、备份恢复和示例接入文档。用干净环境复核 Compose 安装，用测试账户和示例请求验收 CPA 和 OpenCode 适配器，记录受支持的协议和版本 |

M2 的目录工作和 M3 的采集工作在 M1 稳定后可并行。每个里程碑以可复现的验收结果收尾。批量回放、评测集和发布门禁继续列在 MVP 之后。

## 第一批任务

| 顺序 | 任务 | 完成条件 |
| --- | --- | --- |
| 1 | 建立 TypeScript workspace 和本地运行入口。准备控制服务、推理入口、后台进程及 Postgres 迁移。复用现有模拟上游与固定镜像 | 按仓库命令启动，迁移可重复执行。能从空数据库启动并得到就绪状态 |
| 2 | 实现管理员登录、项目与环境创建、Key 签发和撤销，再接功能点注册接口 | 同一环境 Key 可登记功能点和查询状态。重复登记保持别名和管理员设置。另一个环境的 Key 被拒绝 |
| 3 | 实现 LiteLLM 模型组创建和读回、静态候选发布、已生效版本读取 | 测试配置只使用模拟来源。发布失败时已生效版本继续可用，并发发布的旧任务无法覆盖新版本 |
| 4 | 实现别名解析、请求 ID、单次尝试和错误分类。保持客户端协议，传递已允许的会话头 | 独立 Responses 和 Chat 功能点可调用。429 可切换备用，400 只有一次上游尝试。流已经输出后中断时不再调用下一候选 |
| 5 | 提供端到端演示与回归脚本 | 从空数据库开始完成创建、签发、登记、发布、调用、限流回退、撤销和回滚。保留示例命令及预期响应 |

第一批任务先使用手工配置的两个模拟候选，便于独立验证身份、别名、发布和回退。首次演示就生成业务 `request_id` 和上游 `attempt_id`，供 M3 直接关联审计与用量。 [路由与推理设计](implementation/routing.md) · [接口与数据设计](implementation/api-data.md)

## 集成验收关注点

| 项目 | 验收时点与证据 |
| --- | --- |
| 路由生效与在途请求 | M1 联调验证数据库生效版本切换。旧请求到达备用时仍使用启动时的候选，新请求使用新版本 |
| SSE 背压、终止和取消 | M1 模拟首事件前失败和首事件后断流，区分可回退与只能结束流的边界。M3 验证审计保留已发送内容和可获取的 usage |
| 事件持久化与统计 | M3 使用重复、乱序和缺失的事件，验证一次业务请求只计一次，每次真实尝试可追踪，未知 token 有独立计数 |
| 可见性与回放权限 | M3 验证未经授权无法查看正文。M4 验证具备权限的操作者可复制并回放，回放作为新调用记录用量 |
| 真实兼容性 | M2 可用测试凭证先验目录和协议，M5 汇总 CPA Responses、OpenCode Chat、会话头、流式和用量的实测结果 |

产品验收场景和详细部署边界见 [产品需求](requirements.md#首版验收) · [实现与验收](implementation/delivery.md)。
