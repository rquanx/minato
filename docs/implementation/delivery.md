# 实现与验收

## 代码边界

首版使用一个 TypeScript workspace 和一个 Postgres 实例。服务可用相同镜像的不同启动命令分别运行。管理界面构建为静态资源，由管理服务同源提供。

| 模块 | 边界 |
| --- | --- |
| `apps/control` | 登录会话、项目环境、功能点注册、配置和审计查询 |
| `apps/ingress` | OpenAI 兼容入口、环境授权、版本解析、请求和 SSE 透传 |
| `apps/worker` | 目录同步、路由发布、事件写入与对账、回放和正文清理 |
| `apps/web` | 管理、调用详情、试运行和回放对比 |
| `packages/contracts` | API 请求与返回模型、版本与审计状态、运行时校验 |
| `packages/db` | 数据库迁移、事务及查询，由三个后端进程复用 |
| `packages/litellm` | 私有管理 API、运行时引用转换、回调载荷适配 |

## 管理界面

| 页面 | 信息和交互 |
| --- | --- |
| 项目与环境 | 显示名称、固定 slug、成员权限、环境 Key 发放和撤销、审计开关和保留期。明文 Key 只在签发完成后复制 |
| 功能点路由 | 稳定别名可复制。显示业务声明、生效配置和草稿，支持选主模型、拖动备用顺序及用键盘调整。预览显示可用候选和能力不匹配原因。发布和回滚后展示任务进度，成功后更新生效版本 |
| 模型来源 | 展示适配器、模型 ID、最近成功时间、目录状态和调用健康。手动同步后可看到新增、下架和恢复的模型 |
| 用量 | 按项目环境、功能点、时间和调用类型筛选，显示请求量、回退率、耗时和已知 token。点击趋势或模型行可跳转到相同筛选条件下的调用列表 |
| 调用 | 列表展示请求时间、结果、用途、实际模型和 token。详情依次展示时间线、逐次尝试、请求和响应。正文不可用时展示关闭、过期、截断或采集失败的状态 |
| 测试 | 编辑请求并选择目标，提交前展示目标和实际发送的内容。历史回放将原始输出和新输出并排展示，参数、模型和 token 变化可直接比对 |

首版使用桌面侧栏和可分享的筛选 URL。移动端将对比视图改为上下排列。交互状态区分保存草稿、发布中、已生效和失败，并保留最近一次成功版本。浏览器状态保留筛选与未提交的编辑值，审计正文和环境 Key 明文只在当前页面内存中使用。

## 部署与运行

- 本地验证运行控制服务、推理入口、后台进程、LiteLLM、Postgres 和可编排响应的模拟上游。开发时通过同源反向代理暴露 `/admin/v1`、`/minato/v1` 与 `/v1`。
- 首版支持 Docker Compose。容器托管平台使用同样的进程边界和持久化 Postgres。LiteLLM、Postgres 和回调入口位于私有网络。云端访问本地上游通过独立私有连接，断开时走功能点预设回退。
- 首次部署执行数据库迁移，再启动后台进程、管理服务和推理入口。升级前备份数据库，固定应用和 LiteLLM 镜像版本。恢复演练验证版本引用、环境凭证、目录和审计保留策略。配置快照可从 Minato 数据重建 LiteLLM 路由。
- 推理入口的就绪检查覆盖 Postgres 和有效 LiteLLM 实例。后台暴露目录快照年龄、发布任务等待时长、采集积压、缺失 usage 率和回放任务状态。关闭实例时先停止接收请求，再等待在途请求到期，并尝试落盘队列。

## 实现顺序

1. **验证底座。** 已用固定 LiteLLM 镜像和两个模拟来源验证协议转换、动态添加模型组和尝试回调。Minato 将按错误类型执行回退，LiteLLM 负责每次上游调用。 [验证记录](../../tools/litellm-compat/README.md)
2. **打通业务接入。** 实现项目环境、环境 Key、登记 API、目录同步、候选预览和路由发布。用标准 OpenAI SDK 分别验证 Responses 和 Chat 功能点的固定别名，并验证 Responses 功能点在回退时保留同一别名。
3. **补齐审计闭环。** 记录客户端与上游尝试事件，汇总 token。完成权限、内容开关、保留期、调用详情和 Prompt 复制。
4. **打通试运行和回放。** 支持手动请求和基于历史请求的单次回放，核对目标、权限、原请求关联和测试用量，在管理页对照结果。

第一批任务和各阶段的交付条件见 [MVP 实施计划](../roadmap.md)。

## 兼容性验证

以下用例先用模拟上游复现，再用测试项目和示例请求验收 CPA 与 OpenCode 适配器。通过后把镜像版本和对应能力写进部署说明。

| 用例 | 可验收结果 |
| --- | --- |
| CPA 原生 Responses | 上游实际收到 Responses 端点、原始模型 ID 和所需参数。网关返回可被客户端 SDK 解析的结构 |
| Responses 回退到 Chat | 模拟首选连接失败、限流或模型下架，确认请求只在允许的错误类型回退。兼容的 JSON 格式、会话头、SSE 结束及 usage 可用 |
| 发布期间有在途请求 | 请求 A 使用旧版本，发布期间启动请求 B，生效后请求 C 使用新版本。A 在回退时仍用旧版候选。模拟发布失败和过期任务，确认当前版本正确 |
| 跨项目、撤销与测试权限 | 项目 A 的 Key 无法使用 B 的别名，也不能指定内部模型组。撤销后，新注册与推理请求均失败。只有具备对应权限的用户能查看正文或执行测试 |
| 目录异常和恢复 | 模拟超时、缺页、空列表、持续缺失和重新出现。确认普通故障保留上一目录，确认下架后自动重新发布，恢复后按已批准策略重新纳入 |
| 用量、回退和采集对账 | 一次逻辑请求触发两次尝试。重复和乱序送达事件后仍对应一条请求和两次尝试，缺失 usage 标未知。流式中断保留部分输出 |
| 默认关闭审计和保留期 | 验证审计关闭时普通记录与正常业务用量可查，正文未写入 Minato 或 LiteLLM 默认日志。开启后可复制脱敏内容，到期后只保留调用元数据 |
| 测试与回放 | 对同一个示例运行当前路由、指定模型和编辑后回放，屏幕展示真实模型及 token。重复提交相同幂等键仅执行一次，远程会话上下文缺失时提示补齐 |
| 服务故障 | 管理服务暂停时已发布推理可运行。审计写入异常时输出正常透传并能观察采集失败。推理鉴权数据库不可用时返回带请求 ID 的 `503` |

运维测试记录保留模型协议、镜像版本、响应样本和断言结果。生产切换以合成流量验收和试运行结果为依据。 [产品需求](../requirements.md#首版验收)
